## 실제 변경

### 얼굴·머리

v2의 타원형 단면 + voxel remesh로 부드럽게 뭉친 얼굴을 그대로 조금씩 밀지 않고, **턱/광대 면과 평평한 중안면을 정의하는 새 연속 얼굴 표면**으로 교체했다. 눈확·눈썹뼈·코·입술·턱끝은 실제 표면의 깊이로 조형. 단면 사이에는 단조 Hermite 보간을 사용해 띠 모양의 법선 꺾임을 제거했다.

- 눈은 가로로 긴 아몬드 개구부, 기울어진 상안검, 실제 두께가 있는 눈꺼풀로 구성.
- 홍채를 눈 개구부에 맞게 잘라 눈 밖으로 검은 원판이 튀어나오지 않게 구성.
- 눈썹은 둥근 튜브 대신 두께와 끝 폭이 달라지는 얇은 입체 리본.
- 코는 별도 덩어리 부착 대신 얼굴 표면의 콧대·코끝·콧방울 조형.
- 귀는 외륜/안쪽 접힘/두께를 가진 표면으로 교체.
- 기존 머리카락 실제 메시에서 뒷머리 부피와 락 사이 얕은 굴곡 조정. 모자는 보존.

**사진과 컨셉의 차이:** 이번에 확인한 [KBO 공식 프로필](https://www.koreabaseball.com/Record/Player/PitcherDetail/Basic.aspx?playerId=68220)의 [2026년 작은 정면 사진](https://6ptotvmi5753.edge.naverncp.com/KBO_IMAGE/person/middle/2026/68220.jpg)에서는 가로로 좁은 눈, 비교적 곧은 눈썹, 모자 밖 긴 옆/뒷머리가 관찰된다. 컨셉은 눈을 더 크고 선명하게, 턱선을 더 날카롭게 과장했다. 새 모델은 컨셉의 눈매/턱 방향을 택하되 실제 사진을 정밀 계측한 얼굴 복원이라고 주장하지 않는다. 작은 정면 사진 하나로 측면 코·턱의 정확한 입체형을 확정할 수 없다. 참조 사진은 `/tmp`에서만 확인했고 모델·게임·검수 이미지에 넣지 않았다. 곽빈이라는 인상은 여전히 사용자 검수가 필요하다.

### 상반신·유니폼

피부 노출을 해결한 v2의 연결된 소매/몸통 메시는 유지하면서 흉곽 앞면, 가슴 아래 전이, 허리 폭, 허리 안으로 넣은 천과 옆구리 긴장 주름을 실제 좌표로 조정했다. 기존 대비 허리 구간의 가로 폭을 최대6% 줄였고, 하단 벨트 접점에서는 변형이 사라지도록 했다. 숫자·이름·가슴 인쇄와 단추/플래킷은 **변경된 셔츠 표면에 raycast로 다시 맞춤**. UV나 번호를 다른 면으로 바꾸지 않음.

목둘레에 접힌 천 띠, 어깨에서 소매로 이어지는 옅은 봉제선을 추가. 흰 천을 가슴·허리 형태에 맞게 보이도록 했지만, 아직 컨셉의 재단/주름을 충분히 재현하지는 못했다.

### 3D 표현 선택

단색 재질만 고집하지 않고, **공유 512×512 색상 맵 + 512×512 tangent normal map**을 실제 셔츠 UV에 적용했다. 작은 직조·봉제·주름 릴리프용이다. 사진/얼굴/카메라별 조명 이미지가 아니다. glTF 표준 PBR baseColorTexture/normalTexture로 내장되어 같은 메시를 어느 방향에서도 렌더링한다. roughness는0.88, normal scale0.55. 별도 toon/GPU 엔진·외부 라이브러리·조명 변경 없음.

두 PNG 합계193,814bytes. 논리적 RGBA 데이터는2MiB, mip 전부 생성 시 약2.67MiB(실제 브라우저 GPU 메모리는 미측정). ON/OFF 비교에서 효과는 작고 주로 확대에서 보인다. 텍스처가 약한 실루엣이나 재단 구조를 해결했다고 주장하지 않는다.

얼굴 본체는21,500삼각형(v2 23,020). 전체 증가는 새 눈꺼풀·귀·접힘 등 부가 표면 때문이며 폴리곤 증가 자체를 개선 지표로 쓰지 않는다. 한 명의 정적 렌더 draw calls는 바닥 포함32→34. 실제 FPS/모바일 GPU 비용을 측정하지 않았으므로 성능 개선 주장은 하지 않는다. 큰 관절 검증도 이번 범위에 넣지 않았다.

- `after/glb-validation.json`: 실제 GLB 파싱. 최대4영향, 미할당0, 정규화 최대오차1.42e−7.
- `verification.json`: **하체·신발·손·벨트·내부 신체·언더슬리브 11개 노드의 POSITION/NORMAL/UV/JOINTS/WEIGHTS/indices가 v2 GLB와 바이트 동일**. 원본42개 본 head/tail/parent는 제작 스크립트에서도 동일성 assert.
- 기존 `viewer.js`(모든 조명/렌더러 설정 포함) 파일 자체와 원래 카메라 프리셋은 불변. 새 얼굴/목 확대 카메라만 양쪽에 똑같이 추가.
- `index.html`, `package.json`, 기존 ABS 조사 메모, rig-contract 불변. 타격/물리/기록/세이브/뉴스/Claude 코드 수정 없음.
- `capture-qa.json`, `after/runtime-inspection.json`: 실제 SHA·본·메시·뷰별 상태, JS 오류0, 동일 모델 인스턴스 재사용.
- `after/provenance.json`: 정적 초상화도 같은 GLB에서 직접 출력.
- `after/cloth-map-test.json`: 실제 WebGL map/normalMap/roughness 상태.

## 미술 평가와 제작 방법의 한계

**기술 검사 통과와 미술 승인은 별개다.** 이번에는 눈과 코·턱, 가슴 아래/허리 전이가 바뀌었지만, 세 장 비교를 보면 컨셉의 의도적인 얼굴 면과 천의 접힘, 소매 재단감과 여전히 차이가 크다. 특히 목이 셔츠에서 자연스럽게 나오고 소매가 천 두께를 갖고 감싸는 표현은 아직 만족스럽다고 판단하지 않는다. 선수 유사성도 미확정.

현재 방식의 한계는 구체적이다.

1. 얼굴을 몇 개의 단면과 국소 깊이 함수로 만들면 치수·연속성은 제어하기 쉽지만, 눈확→광대→입 주변으로 흐르는 면을 작가가 직접 설계하는 수준의 통제가 부족하다.
2. v2의 셔츠는 원통/loft를 voxel union한 등방성 삼각형 표면이다. 그 위에 변위를 주는 방식은 가슴·허리 두께는 바꿔도 목둘레·암홀·소매 끝의 실제 패턴과 두께를 설계하는 데 한계가 있다.
3. 이번 cylindrical UV는 표면 디테일 검증에는 쓸 수 있지만 소매/겨드랑이에서 늘어남이 있어 최종 아트용 봉제 패턴 UV로 보기 어렵다.
4. 미세한 normal map은 원단을 보조할 뿐, 컨셉의 큰 접힘이나 잘못된 면 흐름을 대신하지 못한다. 조명을 세게 바꾸면 더 극적으로 보일 수 있지만 이번 비교에서는 하지 않았다.

**권고:** 3D와42본/identity/동일 모델 재사용 구조는 유지하되, 동일한 자동 단면·변위 조정은 여기서 중단한다. 다음 아트 제작은 현재 `.blend`를 가져가 얼굴의 눈확·광대·턱 면을 직접 sculpt하고, 셔츠는 목둘레/암홀/소매에 맞는 quad edge flow와 두께를 가진 의복 메시로 다시 제작하는 편이 현실적이다. 주름을 실제 sculpt한 뒤 공유 UV/normal map에 bake하는 방식이 적합하다. DCC에서 직접 조형·리토폴로지 작업 후 같은 골격에 바인딩하여 기존 뷰어에서 검수한다. 외부 아트가 필요하다면 제작자·라이선스·비용을 별도 결정해야 하며 이번에 외부 서비스/유료 자산을 도입하지 않았다. 생성 이미지를 3D 구현 성과로 바꿔 보고하지 않는다.

이번 한 차례 후보를 보존하고 외형 검수 대기. 추가 자동 수정/다른 선수/긴 모션/게임 통합으로 넘어가지 않는다. iPhone Safari 및 실기기 성능 미검증. 기존 ABS/슬로 리플레이 조사 항목은 별개로 그대로 유지하며 수정하지 않았다.

## 재현 및 소스

`visual/player3d-study/refine_face_upper.py`: v2 `.blend`를 입력으로 받아 선택된 얼굴/상반신을 수정하는 독립 패스. 하체·본 보존 assert 포함. 원본 복원 가능한 v2 기준 커밋은 `a0210a4`.

별도 checkout에서 v2 `.blend`를 확보한 뒤:

```
blender --background --python visual/player3d-study/refine_face_upper.py -- /tmp/kwak-v2.blend
```

이 명령은 현재 `.blend`와 GLB를 새로 생성한다. v3를 입력으로 다시 적용하는 명령이 아니다. 초상화/매니페스트는 새 실제 출력으로 별도 갱신 필요. 기존 `assets/qa/unmerged.glb`는 **v2 병합 검증 fixture**로 남겨둔 것이며 v3의 병합 전 원본이라는 뜻은 아니다.
