# RECOVERY / ABS・삼진 리플레이 시각·성능 마무리 후보

검증일: 2026-10-30 (Asia/Seoul). 기준 후보 `6a67ec7`, 별도 브랜치 `fix/replay-framing-performance`. 최신 Claude `a525d7ad8afaa2a55d85cbcd29f4ed6146e399da`, 서비스 v5.175.3 / Pages main `25205ece2dbbeda02c5ee81e728a4a575f7bf744`. 두 후보는 같은 최신 Claude 소스 위에서 비교했다. 실서비스·3D 연구·다른 Claude 변경은 수정하지 않았고 병합/Pages 배포도 하지 않았다.

## 확인한 원인과 최소 변경

### ABS 첫 장면의 화면 밀림

기존 첫 장면은 존 중심으로 1→2.5배 확대한다. 390×844에서 타자 중심의 가로 오프셋은 약98px인데, 확대 후 최대246px이 되어 화면 오른쪽 밖으로 나간다. 투수 발 위치도 화면 하단 밖으로 이동한다. 실제 월드 좌표 부호나 타자 이동 문제가 아니라 의도된 카메라 확대가 전신 구도를 깨는 경우다.

후보는 첫 장면의 전신 구도를 유지하고 두 번째 장면에서 기존 존 확대를 보여준다. 구역·공 경로·판정 사건 시계는 그대로다. PC에는 별도 문제가 있어 기존 투수 기준점 H×1.04를 H×0.96으로 이동했다. 모바일 H×0.98은 유지했다. 공 릴리스 위치는 변경된 실제 투수 기준점을 같은 helper로 투영한다.

### 리플레이 중 중복 렌더링

기준 후보의 전체 삼진 profiling에서 이미 replay에 가려진 일반 타석 mvPaint 호출이 32회 관측됐다. 새 replay actor에 더해 원래 RECOVERY actor를 같은 프레임에 그리고 있었다. 그래서 replay draw 비용만 보면 프레임 전체 부하를 과소평가한다.

후보는 ABS/삼진 replay로 명시된 overlay가 완전히 불투명해진 뒤에만 아래 일반 타석의 raster 작업을 건너뛴다. `_mv` 상태와 절대 시계, 결과 처리는 계속 진행한다. 입장 fade 260ms 동안은 실제로 보이는 아래 장면을 유지하며, 퇴장 fade 직전에는 현재 시계로 아래 타석을 다시 그린다. 다른 오프닝/국가연주 overlay에는 적용하지 않는다. 애니메이션 RAF를 중단하거나 판정을 지연시키는 최적화가 아니다.

### actor 자체의 비용

소프트웨어 깊이 래스터, 6개 팔/손 부분의 Canvas readback 및 픽셀 가림 검사가 여전히 주요 비용이다. 기존 원본 해상도·레이어·깊이 수식은 유지했다.

- 작업용 Canvas의 크기가 같으면 width/height를 다시 할당하지 않는다. 각 부분의 명시적 clear/state 설정은 유지한다.
- 완전히 동일한 READY(0ms), FINISH(1750ms)의 scene 계산만 factory당 최대2개 재사용한다. 시간 양자화·프레임 건너뛰기·텍스처 해상도 저하·합성 이미지를 사용하지 않는다.
- 새로운 GPU/Worker 경로, 렌더러 재제작, 공격 포즈 재설계는 하지 않았다.

정방향/반대편/RECOVERY 26개 동일 조건 actor render의 RGBA가 기준 후보와 완전히 일치했다(`pixels.json`). 이는 검사한 26개 조건의 결과이며 모든 브라우저/모든 1ms 포즈의 비트 동일성을 전수 증명하는 것은 아니다.

## 성능 자료 읽는 법

`bench.json`은 총80회 실제 타격: PC/390×844 viewport × supported/실제 외곽 reach fallback × before/after ×5쌍 ×쌍당 첫/연속 타격이다. 같은 쌍의 두 타격은 같은 페이지/타자에서 실제 다음 공으로 진행한다. before/after 순서를 쌍마다 바꿨다. 녹화·CPU profiling을 동시에 하지 않았다.

`inputCost`는 자동화가 실제 act()를 호출해 돌아올 때까지의 동기 처리 시간, `inputToRaf`는 그 호출 후 첫 RAF callback까지다. 실제 손가락 터치→광자 지연이나 iPhone 입력 지연이 아니다. 입력 표본은 세부 조건당5개이므로 P99는 사실상 최대값이다.

`bench-summary.json`은 각 조건의 모든 RAF 간격을 합친 P95/P99와 33.3ms 초과 비율, 각 실행 P95를 함께 남긴다. 33.3/33.4 경계는 타임스탬프 반올림에 민감하다. 단일 P95나 평균 FPS만으로 성공을 판단하지 않는다.

리플레이는 별도 `replay-bench.json`으로 PC/mobile 각각 before/after5회씩 전체 삼진을 측정했다. 이 자료는 `6a67ec7` 후보와 이번 후보의 비교이며, 역사적 다른 환경의 16.8ms 수치를 비교 대상으로 섞지 않았다.

## 모션 검수의 한계

650ms RECOVERY 포즈/진행 곡선/C1/원본5단계는 이번에 바꾸지 않았다. 처음/연속 타격의 원본 RAF 및 정상속도 전체 연결 영상을 제출한다. 지오메트리나 끝점이 연속이라는 이유로 자연스러움이 최종 승인됐다고 해석하지 않는다.

삼진 영상은 같은 사건 시계에서 전신을 확인하며, 5ms 간격의 투수 손/회복 그립·배트/발 궤적은 `kinematics.json`에 별도로 남긴다. 기존 투수의 key pose easing과 C1의100ms 압축 때문에 느린 재생에서 동작이 기계적으로 읽히는 부분은 남을 수 있다. 원본을 임의로 수정해 숨기지 않았다. 이번 결과는 새 투구/타격 애니메이션 제작이 아니다.

## 보존 및 남은 위험

- 승인 5포즈 및 카메라 원본 스냅샷, adapter의 C1, recovery 파일, 구장 캐시 파일 모두 기준 후보와 바이트 동일(`integrity.json`). 런타임 최적화는 build 어댑터에만 있다.
- 판정·물리·세이브·기록·리그 함수 동일성 및 결과 일회 반영 검사를 유지한다. 새 저장 필드를 추가하지 않았다.
- 실기기 iPhone Safari 미검증. desktop Chromium의 모바일 viewport 성능과 구분한다.
- 동작의 자연스러움과 최종 화면은 사용자 미술 검수 대상이다.
- 일반 타격 supported의 약33ms 프레임은 남는다. 이번 후보를 60fps 복구 또는 배포 가능으로 보고하지 않는다.
- 이 렌더러를 야수 여러 명에 단순 복제하면 프레임 예산을 초과할 위험이 있다. 1명 replay 결과가 다인 성능 검증을 대신하지 않는다.

검수 미디어만 별도 review 브랜치에 공유하며, 실서비스 병합·배포는 하지 않는다.

## 최종 검증 결과

- `e2e.json`: 헛스윙→다음 투구, 파울→다음 투구, 삼진 전체 replay→다음 타자, ABS 전체→같은 타자 다음 공, 4개 실제 controller 흐름 통과. 모든 JavaScript 오류 배열은 비어 있다.
- `replays/*/trace.json`: 삼진 우타/좌타×우투/좌투4조건, ABS 우우/좌좌2조건 캡처 완료. 각 overlay 종료까지 캡처했고 JavaScript 오류 없음. 다음 타석까지 이어지는 핵심 검수는 별도 e2e-media/complete-mobile.mp4를 사용한다.
- `geometry.json`: 3×3 코스5 supported /4 기존 reach fallback 유지, 공/배트 목표 투영 오차 약1e-13px, 원본 C1 표본·연결 검사 및 좌타 fallback 통과.
- `scenarios.json`: 실제 엔진의 헛스윙/파울/안타/홈런/삼진/좌타 결과와 기존 필드 전환 통과. 모든 조합을 전수 검사한 것은 아니다.
- `result-flow.json`: 안타 결과 PA0→1, 안타1, 강제 결과 일회 소비, 저장/로드와 player/round 유지.
- `isolation.json`: 판정/공 물리/저장/기록/리그/성장 및 기존 투수·캐릭터 관련20개 함수가 최신 Claude와 동일.
- `integrity.json`: 원본 포즈, 기존 recovery/C1/구장 캐시 보존. 별도 runtime generation만 최적화.

## 영상 및 시각적 검수 판단

`e2e-media/whiff-next/complete-mobile.mp4`는 원본 RECOVERY650ms와 다음 투구까지 보여준다. raw RAF는 `bench.json`에 있으며, 대표 실행만 그린 `frame-times.png`는 전체 집계를 대신하지 않는다. 정상속도 영상은 브라우저 실제 진행을 녹화한 것이지만 비디오 인코딩의 FPS를 RAF 성능으로 사용하지 않았다.

`ABS-framing-comparison.png`와 `framing/`은 동일 실제 replay closure를 k=.25/.5/.82/.95에서 렌더한 비교다. 첫 장면에서 타자와 투수가 잘리지 않게 됐으며, 다음 존 확대 beat는 유지된다. 실제 전체 전환은 `abs-next/complete-mobile.mp4`로 확인한다.

전신 동작의 명백한 프레임별 상태 교체/순간이동은 이번 캡처에서 발견하지 못했다. 다만 투수 key-pose easing, SD 고정 몸통 표현, C1의100ms 시간 압축 때문에 기계적인 인상은 일부 남는다. RECOVERY가 사람다운 동작이라는 미술적 최종 판정은 내리지 않는다. 이번에는 모션 곡선이나 관절을 다시 제작하지 않았다.

비용 상세와 조건별 실제 P95/P99/초과 비율/입력 시간은 [MEASUREMENTS.md](MEASUREMENTS.md)에 정리했다. **ABS 구도와 리플레이 중복 렌더링은 개선, 일반 supported 타격의 프레임 안정성 및 미술 최종 승인은 보류**가 이번 결론이다.
