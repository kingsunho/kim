# 곽빈 실제3D — 1~3단계 외형 검수 후보

2026-10-28 / 별도브랜치 `visual/kwak-3d-identity-study` / 기준 `5aca0ba`.

위3D 결과는 **실제 Three.js/WebGL 렌더 캡처**다. Blender의 별도 미화 렌더나 이미지 생성 모델의 결과로 대체하지 않았다. 컨셉 비교 왼쪽만 이전 생성 시트에서 발췌했다. 두 전신은 비슷한 표시 크기와 같은3/4 방향으로 놓았으며, 컨셉의 무릎/팔 자세와 현재 중립 자세에는 차이가 있다. 얼굴·몸통 비례를 이미지 변형으로 맞추지 않았다.

## 실제 구현된 것

1. **메시와 재질**
   - 코·턱·볼 윤곽을 가진 얼굴 표면, 곡면 위 눈/눈꺼풀/눈썹, 입, 귀, 연속된 머리카락 형상을 직접 제작했다.
   - 몸통·목·사지의 공통 신체, 흉곽부터 소매까지 연결된 셔츠, 골반·사타구니·양다리가 연결된 바지, 손가락을 포함한 손과 신발을 모델링했다.
   - 단순 구체/원통을 각각 뼈에 붙인 프록시로 완료 처리하지 않았다. 최종 의복/신체 표면은 이어진 메시이며, 세부 파츠도같은 하나의 스킨 계층에 묶여 있다.
   - 무광 애니메이션풍을 목표로 하며 사진 피부 텍스처는 사용하지 않았다. glTF 내 이미지 텍스처0개,색상/roughness재질14개와 실제형상으로 표현한다.
2. **실제 스켈레톤과 스킨**
   - 단일 스킨,42개 뼈대. 골반/척추/흉곽/목/머리,쇄골/상완/전완/손,손가락/엄지,허벅지/종아리/발,눈의 명명된 계층이다.
   - 실제GLB의 모든 메시 프리미티브에 `JOINTS_0`/`WEIGHTS_0`를 확인했다. 최대4영향,미가중 정점0,가중치 합 오차 최대약1.38e−7.
   - 이것은 데이터 유효성 검사다. **큰 동작에서 어깨/사타구니가 자연스럽게 변형된다는 검증이 아니다.** 자동 근접 기반 가중치는 후속 동작 검사에서 수정이 필요할 수 있다. 아직 IK 제어 리그/지지발/균형 시스템이 아니다.
3. **동일 모델을 여러 구도로 렌더**
   - 카메라만 바꿔0°/−35°/−90°/180° 외형,전신,정자세,상반신,얼굴,중거리구도를 만든다.
   - 모든 구도에서 같은 모델SHA,같은 메시 객체UUID목록,같은 재질/중립 자세/identity를 확인했다. 모델/그림을 장면별로 교체하지 않았다.
4. **정적 초상화 생성**
   - 같은 실제GLB를 WebGL에서 렌더해420×420 투명PNG3장을 추출했다. provenance에identity/appearanceVersion/modelSHA/preset을 기록한다.
   - `portrait-only.html`은 PNG만 사용하는 독립 검수 페이지다. WebGL context 요청0을 확인했다. 기존 게임의 초상화/UI는 변경하지 않았다.

## 실제 자산과 소스

비공개 소스브랜치의 `visual/player3d-study/`:

| 파일 | 역할 |
|---|---|
| `assets/kwak-source.blend` | 편집 가능한 실제 메시·Armature·가중치·재질 |
| `assets/kwak-v1.glb` | 실제 브라우저에서 읽는 단일 캐릭터 팩 |
| `build_model.py` | Blender4.3.2 제작/내보내기 레시피 |
| `assets/rig-contract.json` | 실제42개 본의 이름·부모·rest 좌표 |
| `identity.json` | 곽빈 외형/팀/번호/자산/장면 간 참조의 명세 |
| `scenes.js` | 모델과 분리된 카메라/프레이밍 설정 |
| `viewer.js` | 한 렌더러/한 장면/한 모델을 사용하는 검수 코드 |
| `bake-portraits.cjs` | 같은 실제 런타임 모델로PNG를 추출하는 개발 도구 |
| `assets/portraits/` | 추출된PNG와provenance |
| `ARCHITECTURE.md` | 현재 구현과 장기 확장 설계의 경계 |

최종GLB: **115,615 triangles /63,823 exported vertices /77 skinned meshes /42 bones /14 materials /단일 skin /약3.49MiB**. 장면의 바닥은별도이며 캐릭터 수치에 포함하지 않았다. 이것은 **근거리 외형 검수 후보**다. 작게그리는것만으로 경량LOD라고부르지않으며,115k메시를18명에게그려도빠르다는주장은하지않는다. 원본 `.blend`와GLB의정확한바이트/SHA는asset manifest와검사자료에남겼다.

Three.js0.160.1(MIT)와GLTFLoader/BufferGeometryUtils만검수디렉터리에고정버전으로두었다. 라이선스/도입근거는 `THIRD-PARTY.md`. glTF스킨과PBR/깊이검사를직접새로작성하는위험을피하기위한선택이다. 기존게임의package.json/엔진/Canvas렌더러는변경하지않았다. 별도클라우드3D서비스,다운로드한인물모델,공식로고벡터,사진얼굴텍스처를사용하지않았다.

## 선수 정체성과 재사용 구조

현재study identity는 `kbo:68220`이며, 기존 게임의 내부선수ID를바꾼것이아니다. 실제GLB extras와manifest identity를대조하고불일치시로딩을거부한다. 로드한바이너리SHA도검사한다. 같은선수의새모델/유니폼을배포할경우모델SHA/appearanceVersion을기준으로초상화캐시를새로만들어야한다.

현재패키지안에서공통body,face/hair,kit,print가별도노드영역으로나뉜다. 가슴문자·모자문자·앞/등번호·백네임은몸통색에그려진사진이아니라독립스킨메시로rest표면에맞춰부착했다. 중립자세의부착은확인했지만동작중프린트와옷의변형이완전히일치하는지는미검증이다.

다른선수는이머리를이름만바꿔쓰는방식으로확대하면안된다. 현재는곽빈외형한명만제작했다. 얼굴morph/체형템플릿/표정/유니폼일괄교체기능을완성했다고보고하지않는다.향후에는공통본규약·신체기본형과선수별고유얼굴/머리/체형,팀별의상/인쇄,표정·시선,장면설정을분리한다. 이번단계의분리는그방향을수용하는자산구조이며완성된전선수생성시스템은아니다.

9/18명으로확대할때는메시·재질·팀/모자자원을공유하되각선수의본포즈상태는독립적이어야한다. 공통리그규약을쓴다는것과모든선수에게같은본행렬을쓰는것은다르다. 렌더러/context는하나를유지해야한다.

근거리/중거리/원거리모델이달라도같은얼굴/체형/본규약/의상버전을보존하는것이목표다. 실제LOD는승인된모델에서파생하고같은화면크기에서얼굴/실루엣오차와전환을검사해야한다. **현재는모든구도에동일HQ메시를사용한다.**

UI는동일마스터의정적이미지를캐시하는방향을실제추출물로보였다.420×420PNG3장을한꺼번에디코드했을때의단순RGBA합은약2.02MiB지만실제브라우저메모리실측은아니다. 실시간장면과PNG카드는모델파일/조명/카메라/의상/표정버전을묶은키를공유해야한다. 현재정적파일명은검수용이며실서비스캐시무효화시스템은아직연결하지않았다.

## 외형에서 남은 차이 — 승인 필요

- 실제3D는컨셉보다얼굴/눈/입/귀의선과색이단순하고,곽빈이라는인식가능성은아직확정하지않았다. 긴얼굴윤곽·낮고곧은눈썹·좁은눈매·목뒤머리를참고했으나실사복제나정확한닮음의보장은아니다.
- 어깨와소매는연속메시지만실루엣이아직둥글고굵게읽히며,손/헤어덩어리/바지주름은컨셉의정교함에못미치는부분이있다.
- 체형은SD중립형이다. 선수고유체형/자세를완성했다고판정하지않는다.
- 로고/숫자는표면에맞춘근사일반글꼴이며공식유니폼폰트아니다. 백네임 `KWAK BIN`은임시영문표기다. 실제한글백네임/패치/스폰서디테일은미반영이다.
- 가중치정상/4방향렌더/identity일치는**고품질미술승인과별개**다. 이단계에서오프닝/국가연주에바로사용해도된다고판정하지않는다.

참고한외형자료는기존에확인한KBO곽빈프로필(playerId68220)과승인방향의컨셉이다. 원본사진은모델/게임/검토자산에넣지않았다.

## 하지 않은 검사와 기존 게임 보호

지시순서에따라 **4단계큰관절7종/연속회전,5단계모바일1/9/18명성능·메모리·기존Canvas합성은아직실행하지않았다.** glTF애니메이션0개. 긴모션,투구,타격교체,주루/수비,다른선수제작없음. 실기기iPhone Safari/FPS/LOD/접지·균형은미검증이다.

기존승인리그의field/world/project를참고할수있지만glTF좌표와축·단위를명시적으로연결해야한다. 소스Blender는Z-up/front−Y,내보낸glTF는Y-up/front+Z다. `scenes.medium`은기존MV카메라정합을증명하는어댑터가아니다. 판정시계/타구결과/기록/저장과표현을분리하는원칙을유지한다.

기존index.html,package.json,승인타격번들/어댑터/구장캐시/기존오프닝등18개파일을기준5aca0ba대비바이트/SHA로보존확인했다. Claude브랜치와실서비스는수정하지않았다. 새디렉터리/자산/보고서만추가했으며 **병합·Pages배포·기존초상화교체없음**.

실행상태/모델UUID동일성은 `runtime-inspection.json`,실제GLB가중치/버퍼검사는 `glb-validation.json`,정적UI의context요청0은 `static-portrait-check.json`,PNG의해시출처는 `portrait-provenance.json`에기록했다.
