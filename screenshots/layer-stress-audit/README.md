# A 레이어형2.5D — 큰 동작·시점·자산 예산 검증

2026-10-28 / `visual/layer-stress-audit` / 기준 `eec9a9b`.

**결론: 현재 A 구현은 공용 야구 캐릭터 관문을 통과하지 못했다.** 계산은 가볍지만, 큰 관절 회전·가슴 앞 가림·흉곽/골반 비틀림·연속 시점의 외형이 유지되지 않는다. 지금 상태로 곽빈의 실제 투구나 게임 통합을 진행하지 않는다. A 전체가 원리적으로 불가능하다는 결론은 아니지만, 이 구현을 조금씩 고쳐 모든 경기 캐릭터로 확대하는 것은 추천하지 않는다. 다음 비교 후보는 **인물 전용 경량3D(B)**이며, B의 실제 품질/성능이 이미 검증된 것은 아니다. 기존 게임 전체의3D 전환을 의미하지 않는다.

## 기본 구현과 계측용 확장의 구분

실행 소스 `visual/pipeline-stress/`. 기본 `visual/pipeline-study/layers.js`와 아트는 **수정하지 않았다.** `build.cjs`가 원본SHA를 기록하고 `probe-renderer.js`를 생성한다. 추가한 훅은 세 가지뿐이다.

1. 기본 FK 대신 외부 관절 좌표를 받는 계측 입력.
2. 실제 투영에0~90° 연속 카메라각을 전달하는 입력.
3. 외부 골격 사용 시 셔츠 중심을 흉곽 위치에 따라 배치하는 앵커 입력.

얼굴·팔다리 아트/파트 변환/가림 순서/상하체 변형은 원본 그대로다. 이미지 crossfade, 부위별 가림 예외, 길이 강제 늘리기, 스타일/카메라 변경 등의 보정은 추가하지 않았다.

| 항목 | 기본 API 여부 | 이번 입력 |
|---|---|---|
| 팔 올리기 | 있음 | 양쪽 상완 roll±175°,고정 관절 길이 |
| 어깨 뒤 젖힘+팔꿈치 | 일부 없음 | 팔꿈치 기본입력 + 어깨 pitch 계측 확장 |
| 가슴 앞 교차 | 있음 | 상완roll±78°,팔꿈치25° |
| 흉곽/골반 반대 비틀기 | 없음 | 흉곽+45°/골반−30°의 외부 골격 |
| 높은 무릎 | 있음 | 고관절−125°/무릎135° |
| 전방 숙임 | 없음 | 흉곽pitch−60°의 외부 골격 |
| 넓은 스트라이드 | 없음 | 계측용2-bone IK,골반22unit하강,발X±67/Y279고정 |

기본 미지원 항목은 기존 기능이 고장났다는 의미가 아니다. **요구된 골격을 입력해도 현 레이어 표현이 이를 따를 수 있는지** 검사한 것이다. 계측용 정적 IK를 실제 투구/주루 시스템에 넣었다고 보고하지 않는다. 모든 관절 데이터는 유한하고 검사한 뼈 길이 최대오차는 약2.1e−14unit이다. 길이가 유지돼도 아래 시각적 실패가 남는다.

## 0→90° 시점 검사

기본 API는3개 view만 받는다. 이번 드라이버는 투영각을 연속으로 변경하면서0/38/90° 중 최근접 아트를 선택했다. 선택 임계값19°와64°는 **검사용 정책**이며 기존게임의카메라전환규칙이아니다. 임계값을옮겨도중간아트가없는사실은바뀌지않는다.

| 비교(각각0.2° 변화) | 같은방향아트내 | 아트전환포함 |
|---|---:|---:|
| 18.7→18.9 / 18.9→19.1 | 변경픽셀1.15% | 57.06% |
| 63.7→63.9 / 63.9→64.1 | 변경픽셀4.14% | 53.70% |

투명배경에서배경을제외한두프레임합집합에대해premultiplied RGBA 절대차합>30인픽셀비율이다. **이비율은오류율이나지각점수가아니라불연속의진단값**이다. readback은이오프라인검사에만사용했고정상렌더루프에는없다.

실제영상에서얼굴형/눈과귀노출/머리모양이단번에바뀌고,Bears/47의위치·기울기도한번에이동한다. 번호 문자열이 다른 선수 번호로 바뀌는 현상은 발견하지 않았다. 그림의표면매핑이연속적이지않다. 고정자산규격도quarter→side에서몸통폭75→48(−36%),골반59→43(−27%),머리81→74(−8.6%)로즉시바뀐다. 어깨/골반관절의투영좌표가연속이어도그림과접점이바뀐다. 팔가림도어깨한쌍의전후관계만으로정하므로손/전완의깊이를보장하지않는다.

현재3방향 방식으로자연스러운연속회전이가능하다고판단하지않는다. 후면/후방3/4자산도없어주루·수비의360°방향은이번체계로검증되지않았다.

## 서로 다른 선수의 자산 예산 — 추정임을 명시

실제원본파트사각형으로계산한3방향RGBA논리크기:

- 머리/얼굴/머리카락:0.936MiB/선수

- 합계7.889MiB(1선수전부독립가정)

|---|---:|---:|---:|

**독립파트현재크기외의공유/LOD행은재패킹이완료됐다고가정한설계추정이다.** 실제다른9/18/36명의얼굴/체형을제작·로딩해검증한값이아니다. GPU사본/PNGdecoder/프레임버퍼/캐시정렬/브라우저내부메모리제외. LOD행은필드머리최대64px,다른필드파트96px,3방향,손4피부색묶음,근접1전체세트를유지하는가정이며그LOD의외형품질은미검증이다. 후면방향과표정·손의그립추가시더늘어난다.

현재로드단위는머리만이아니라파트가묶인3개아틀라스다. 선수별아틀라스를그대로늘리는구조는채택하면안된다. 팀셔츠에47이그려져있는현재자산은다른선수의팀몸통으로그대로공유할수도없다. 공유행을실현하려면다음분리가선행돼야한다.

1. 체형별공통명암/사지/하체,피부색별손과팔을공유.
2. 팀색마스크,가슴로고/모자마크/패치,이름/등번호인쇄를독립레이어로출력. 글리프/패치아틀라스를공유하고선수번호만조합.현재미구현.
3. 선수별머리/얼굴,머리모양,표정은선택적로드. 체형차이는무제한늘리기가아니라소수템플릿+제한된길이/폭파라미터.
4. 자산키를`body/build/part/direction/lod`, `kit/team/variant/part/direction/lod`, `face/player/expression/direction/lod`, `cap/team/variant/direction/lod`, `hand/skin/grip/direction/lod`로분리. 포즈별전체캐릭터PNG캐시로늘리지않는다.
5. 현재보이는자산은pin/reference count로보존. 화면을떠난항목만LRU회수. 부드러운예산32MiB/상한48MiB는**제안된decoded논리예산**이며실기기보장값이아니다. 초과예상시비노출자산회수→필드LOD하향→근접전환전에새자산준비. 보이는얼굴을중간에없애는방식금지.
6. decode동시성2개,컷전환전미리로딩,해당경기의두팀과보이는9~13명위주로유지(양팀소개등18명이필요한장면은별도예산). 모든리그/모든스페셜유니폼을상주시킬필요없음. 장면종료시lease해제. 현재로더는이공용정책의완성판이아니다.

투영길이와폭을분리하는수정이나관절겹침개선은일반적인수정으로가능하며A방식의본질적불가능을뜻하지않는다. 그러나이번실패는그한가지뿐아니라방향별외형/상하체회전/부분깊이/비례/후면자산까지걸쳐있다. 미검증A에예외를계속쌓아서비스공용으로확대하는것은피한다.

현재얼굴·유니폼의디자인은버리지않는다. B를검토한다면그디자인을모델링/텍스처의기준으로삼고**곽빈한명,투명인물레이어하나**만실제품질/스키닝/동일7종/같은카메라/다인물부하로비교해야한다. 지금3D모델을만들거나엔진/외부라이브러리를도입하지않았다. B도메모리공유/가림/작화검수없이자동으로성공하는것은아니다.
